# 卫星热控单元 · 自适应诊断树综合工作台

纯前端 TypeScript + React 工作台：给定 3–14 种故障、2–20 项试验（每项正整数耗时、
每个故障在每项试验下的 0/1 读数），**精确**综合一棵自适应诊断树，使排故的

1. **最坏累计耗时**最小（首要目标）；
2. 在此前提下 **最坏试验数**最小（次要目标）；
3. 再同值时，取「节点记试验编号、按 0 支后 1 支展开」的**先序序列字典序最小**者。

全部计算在浏览器本地完成，无任何网络请求。

## 功能

- **矩阵编辑器**：增删故障/试验、编辑编号与正整数耗时，读数格点选循环 `0 → 1 → 空`。
- **错误定位**：重复编号（故障行/试验列）、矩阵缺项（具体单元格红框）、非正/缺失耗时
  都会就地高亮并在问题清单中给出行列位置；存在错误时不生成树。
- **不可区分分组**：若干故障的完整读数向量相同时，明确列出不可区分组并说明诊断树不存在。
- **即时撤旧**：输入每次变化都同步重算，旧树立即撤下，不会展示过期结果。
- **可展开诊断树**：每个内部节点显示所用试验、耗时与当前候选集；0/1 分支分别着色；
  内部节点保证只使用**能真正分裂当前候选集**的试验，每个叶节点唯一确定一种故障。
- **逐步回放**：点选任一故障，可上一步/下一步/起点/终点回放，逐步展示
  试验、读数、试验后剩余候选集与累计耗时，并在树上高亮当前路径。
- **JSON 导入/导出**：支持读数按故障顺序的数组，或按故障编号键控的对象。

## 数据格式

```json
{
  "faults": ["加热器开路", "温控阀卡滞", "管路泄漏"],
  "tests": [
    { "id": "红外测温", "cost": 5, "readings": [1, 1, 0] },
    { "id": "压力测试", "cost": 8, "readings": { "加热器开路": 0, "温控阀卡滞": 0, "管路泄漏": 1 } }
  ]
}
```

`cost` 可为数字或数字字符串；读数只接受 0/1，缺失或非法值会作为矩阵缺项/非法值被定位。

## 算法

故障集用位掩码表示（n ≤ 14，共 2¹⁴ 个子集）。对子集 S 定义

```
g_S[d] = 子树 S 在「最多 d 层试验」限制下可达的最小最坏代价上界（不可行为 +∞）
g_S[0] = ∞（|S|≥2）
g_S[d] = min over 能分裂 S 的试验 t:  w_t + max( g_{S∩0(t)}[d−1], g_{S∩1(t)}[d−1] )
```

单故障子集为叶，g=0。按子集大小递增 DP；全局 C* = g_全[n−1]，
L* = 使 g_全[d] = C* 的最小 d。建树时在满足 `(深度 ≤ d, 代价 ≤ C)` 的试验中
取编号最小者作为根（先序序列首位即根，故直接保证字典序），再对 0/1 子树独立重建。

`src/lib/solver.test.ts` 含 300 组随机模型与暴力枚举全部决策树的对拍，
逐项验证最坏代价、最坏试验数、先序字典序一致。

## 本地开发

```bash
npm ci            # 或 npm install
npm run dev       # 开发服务器
npm test          # vitest 单元测试
npm run typecheck # tsc 严格类型检查
npm run build     # 类型检查 + 生产构建到 dist/
npm run smoke     # 对静态服务做 HTTP 冒烟（需先启动服务）
```

## Docker

镜像默认启动零依赖 Node 静态服务器（托管 `dist/`，提供 `/health`，带容器 HEALTHCHECK）。

```bash
# 构建并启动站点（宿主机端口可用 HOST_PORT 配置，默认 8080）
docker compose up -d --build
# 自定义宿主端口
HOST_PORT=9090 docker compose up -d
curl http://localhost:8080/health   # {"status":"ok"}
```

一次性校验服务 `verify`：依次执行 **单元测试 → 类型检查 → 生产构建 → HTTP 冒烟**，
全部完成后自行退出，并以退出码报告结果（0 成功，非 0 失败）：

```bash
docker compose build             # 构建镜像（web 与 verify 共用）
docker compose run --rm verify
echo $?                           # 0 表示全部通过
```

也可在容器外执行等价脚本：`sh scripts/verify.sh`。

## 目录结构

```
src/
  lib/
    model.ts      编辑期数据模型与常量（3–14 故障、2–20 试验）
    validate.ts   尺寸/编号/耗时/读数矩阵校验与不可区分分组
    solver.ts     位掩码 DP 综合器、树回放与统计
    jsonio.ts     JSON 导入/导出
    sample.ts     内置示例
    solver.test.ts 算法正确性（含暴力对拍）与校验/导入测试
  components/     Editor / TreeView / Playback
  App.tsx         编辑→校验→综合→展示的联动
scripts/
  serve.mjs       生产静态服务器（/health、SPA 回退、防路径穿越）
  smoke.mjs       HTTP 冒烟
  verify.sh       一次性校验入口（compose verify 服务）
Dockerfile        构建静态站点镜像（含 HEALTHCHECK）
docker-compose.yml web 服务 + 一次性 verify 服务
```
